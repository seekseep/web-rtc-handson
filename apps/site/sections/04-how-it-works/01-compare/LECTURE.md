# 01 他人の変更は、どうやって届くのか

![静的サイト・動的サイト・WebSocket・WebRTC の 4 つを並べる](./images/00-thumbnail.svg)

前の章で、2 台の端末がつながりました。自分が押したボタンで、相手の丸が光っています。

この章では、**いま動いているものを分解して見ます**。コードは書きません。
手元の `app/` を開いたまま、3 つの節を読んでください。

1. Web で「他人の変更が届く」やり方を **4 つ並べて**、自分が使ったのがどれかを確かめる（この節）
2. **WebRTC が何を解決している技術なのか**を見る
3. `あいてを待っています…` のあいだに、**実際に何が起きていたのか**を見る

「自分が押したことが、**相手の画面にその場で出る**」——ずいぶん当たり前のことに聞こえますが、
Web でこれをやるのはいちばん難しい部類に入ります。
いちばん届かないところから順に、4 段階で上げていきます。

## その前に — ダブルクリックで開いていたとき

[03 章 01 節](../../03-connect/01-light/LECTURE.md) で `index.html` をダブルクリックしたとき、
アドレスは `file:///Users/you/app/index.html` でした。これは「**このパソコンの、このファイル**」を
指す書き方で、通信は起きていません。Wi-Fi を切っても動きますが、**そもそも他人がいません**。

![自分のパソコンの中でファイルを開くだけで、相手には何も届かない](./images/01-local.svg)

_図: ひらいているだけ。ネットワークは動いていない。_

::preview[押しても、パソコンの中で終わる]{demo="01-local" height="250"}

## 静的サイト

[Netlify](../../01-introduction/03-netlify/LECTURE.md) に置いたファイルを、`https://` で開く形です。
ブラウザが「ください」と言い、サーバーがファイルを返して、**接続は切れます**。
他の人も同じページを開けるようになりますが、**開いた人どうしはまだ何の関係もありません**。

![自分と相手が同じサーバーからページをもらう。ただし 2 台のあいだには線が無い](./images/02-http.svg)

_図: 同じページをもらっただけ。自分と相手はまだ他人同士。_

::preview[サーバーから 1 往復もらって、それで終わり]{demo="02-http" height="270"}

## 動的サイト

サーバーにデータベースを付けて、**書いた内容をためておける**ようにした形です。掲示板や社内の申請システムがこれです。
他人の変更も見えるようになりますが、**見えるのは自分が聞きにいったときだけ**です。
通信を始めるのは、いつもブラウザの側だからです。

![相手の書きこみはサーバーと DB に残るが、自分の画面へは勝手に届かない](./images/03-database.svg)

_図: 保存はされている。それでも自分の画面は、こちらから聞くまで変わらない。_

::preview[保存はされる。それでも自分から聞くまで届かない]{demo="03-database" height="330"}

## WebSocket

最初に 1 回だけ挨拶して、**そのあと接続を閉じない**形です。アドレスは `wss://` で始まります。
**サーバーの側から送り出せる**ので、聞かなくても届きます。ただし通り道はサーバーで、
相手の言葉はいったんサーバーに預けられてから配られます。チャットや共同編集の大半はこれです。

![自分の言葉がサーバーを経由して相手に届く。線はつなぎっぱなし](./images/04-websocket.svg)

_図: 速いけれど、通り道はサーバー。_

::preview[つないだまま、サーバー経由で届ける]{demo="04-websocket" height="240"}

## WebRTC

**真ん中のサーバーを外して**、ブラウザ同士を直接つなぐ形（P2P）です。03 章で PeerJS を使って書いたのがこれです。
データは**誰も経由せずに**相手へ届きます。ただし、**つなぎ始めるときだけ**はサーバーを使います。

![自分と相手のパソコンが直接つながっている](./images/05-p2p.svg)

_図: 自分の言葉が相手に直接届く。あいだに誰もいない。_

::preview[最初だけサーバー、そのあとは直接届く]{demo="05-p2p" height="270"}

## 4 つを並べる

|                  | 静的サイト | 動的サイト | WebSocket    | WebRTC         |
| ---------------- | ---------- | ---------- | ------------ | -------------- |
| アドレス         | `https://` | `https://` | `wss://`     | 無い           |
| 話す相手         | サーバー   | サーバー   | サーバー     | 相手のブラウザ |
| 通信するとき     | 開いたとき | 聞いたとき | ずっと       | ずっと         |
| 聞かなくても届く | 届かない   | 届かない   | 届く         | 届く           |
| 相手に届く道     | —          | サーバー   | サーバー経由 | 直接           |
| 記録を残せる     | —          | 残せる     | 残せる       | 残らない       |
| 人数が増えたとき | 平気       | 平気       | 平気         | つらい         |

WebRTC にアドレスが無いのは、相手を URL ではなく「あいことば」で呼ぶからです。

**右へ行くほど偉いわけではありません。**
記録を残したいなら動的サイト、ただ読ませたいだけなら静的サイトで十分です。
今回は「その場にいる 2 人が、いま同時に描く」ものだったので、
[02 章 02 節](../../02-design/02-plan/LECTURE.md) で WebRTC を選びました。

:::notice
[05 章の最後](../../05-drawing/08-deploy/LECTURE.md) では、**自分が描いたものを覚えておいて、
あとから入ってきた相手に送り直す**ようにします。「記録が残らない」を、
自分のブラウザの中だけで小さく埋め合わせる工夫です。
:::

:::questions

- `file://` で開いたページは、Wi-Fi を切っても表示できる [o]
- 静的サイトに公開すれば、開いた人どうしが自動的につながる [x]
- DB を置けば、相手が書いた瞬間に自分の画面も変わる [x]
- WebSocket では、サーバーの側から送り出すことができる [o]
- WebSocket でつないだ 2 つのブラウザは、直接つながっている [x]
- WebRTC で送ったデータは、サーバーに保存されない [o]

:::

4 つのうち、WebRTC だけが仕組みからして違います。
**その WebRTC とは、そもそも何をするための技術なのか。**
